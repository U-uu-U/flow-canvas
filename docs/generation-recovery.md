# 任务产物恢复

任务记录中的“拉取产物”只查询已有任务并下载结果，不提交新的生成请求，不重新上传参考素材。图片、视频、已中断、断连、失败和已完成的任务都可以使用。旁边的连接图标可补填服务商后台的任务 ID，复制图标可复制已有 ID。

## 恢复顺序

1. 主进程从 `data/generation-recovery` 读取原项目、原节点、API 路线、模型、上游任务 ID、异步 Location 和下载检查点。记录不保存 API Key。
2. 已下载且仍存在的产物直接复用。否则使用原 API 账号查询上游任务，不使用当前选择的其他生成模型。
3. 查询支持标准图片任务、通用任务、原生 MJ 和已有的视频 Provider 路线；502、限流、网络中断、暂时未同步的任务及完成但尚未给出地址的响应有界重试。单次查询有超时，产物下载也有超时和临时错误重试。
4. MJ 四宫格沿用四张候选拆分逻辑。结果按项目通过主进程画板服务串行回填，保留节点显示尺寸、提示词和产物列表。
5. 重复点击合并为同一个恢复请求，后续点击复用本地检查点；已落图的产物不会重复追加。切项目不改变落图目标。

原节点在恢复过程中被编辑或删除时，回填报出冲突并保留下载文件。再次明确拉取会重新检查；已有其他产物不会被旧任务覆盖，必要时创建关联的恢复节点。停止拉取只停止本地等待，不表示上游任务被取消。

## 兼容范围

旧任务记录可直接使用保存的任务 ID，或手工补填 ID。新版本开始独立保留主进程检查点，任务记录面板打开时会补回前端遗漏的记录。

上游没有查询接口、任务已过期、账号无权读取，或同步生图中断前既没得到任务 ID 也没下载结果时，不能凭本地记录重建服务端产物；会显示实际错误，不自动变成新的付费生成。
